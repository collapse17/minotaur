# JSON-конфигурация Minotaur

Конфигурация загружается при старте из `public/config` (в собранном приложении — из ресурсов интерфейса). После правки перезапустите/обновите приложение; для поставки пересоберите приложение.

- `app.json`: версия набора, путь к каталогу шаблонов и список файлов разделов. Чтобы добавить раздел, добавьте файл в список.
- `templates.json`: версии шаблонов и исходные параметры действий.
- `prepare.json`, `configure.json`: название и оформление раздела, wizard, правила исполнения и исходные профили.

## Версии

`schemaVersion: 1` — версия формата. Версии выше поддерживаемой отклоняются; равные и более старые принимаются с проверкой структуры. `version: "1.0.0"` — версия содержимого. Профиль фиксирует `templateVersion` каждого действия; более новая версия отклоняется, равная или старая принимается. При редактировании профиля увеличивается revision; version остаётся версией совместимости. Отчёт сохраняет версии приложения-конфигурации, раздела и каталога, снимок мастера, профиль и введённые значения.

Сохранённые профили имеют отдельный версионируемый контейнер и `baseVersion` раздела. baseVersion ниже или равная версии раздела принимается; более новая отклоняется с ошибкой. Старые профили прототипа без версий автоматически переносятся в формат v1 при первом запуске. JSON-импорт теперь требует версионируемый профиль.

Локальные изменения профилей имеют приоритет над исходными профилями JSON. Экспортируйте важные профили перед обновлением конфигурации. Редактор меняет локальную копию, а не файлы поставки.

## Шаги мастера

`wizard` — массив произвольного количества шагов. Поддерживаются типы:

- `form`: поля из `fields`;
- `profile`: выбор профиля раздела;
- `review`: введённые значения и план;
- `execution`: прогресс выполнения;
- `result`: результат и скачивание отчётов.

Поля `id`, `label`, `title`, `description`, `notice`, `errorTitle` задают содержимое. `buttons` задаёт подписи кнопок. Шаги profile, review, execution, result должны встречаться по одному в указанном порядке; формы располагаются до review. Переходы определяются типами, а не числовыми индексами. Новые типы компонентов требуют реализации в движке.

Пример дополнительного шага перед проверкой:

```json
{
  "id": "location",
  "type": "form",
  "label": "Расположение",
  "title": "Где установлен компьютер?",
  "fields": [
    { "id": "room", "type": "text", "label": "Кабинет", "required": true, "default": "", "maxLength": 30 },
    { "id": "remote", "type": "checkbox", "label": "Удалённое рабочее место", "default": false }
  ],
  "buttons": { "back": "Назад", "next": "Далее" }
}
```

Типы полей: text, textarea, number, select, checkbox. Для select задайте `options: [{"label":"Офис","value":"office"}]`. Проверки: required, pattern, maxLength, min/max для number; error — сообщение проверки. Идентификаторы полей уникальны в разделе. Значения собираются в `inputs` отчёта. Не добавляйте пароли: защищённое хранение пока не реализовано.

Поле computerName используется для подписи отчёта; остальные значения также сохраняются. Исполнитель пока демонстрационный: подстановка новых полей в реальные административные сценарии будет реализована вместе с исполнителем.

`rules.requiredTemplates` требует по одному включённому действию каждого указанного типа, `lastTemplate` задаёт последний шаг профиля. Профили и шаги содержат стабильные id, названия и версии. Добавление новых разделов/форм не требует изменения JS; добавление нового нативного обработчика требует кода.

Проверки: `node --test tests/config.test.js`. Сборка: `npm run build`.
