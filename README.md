# Minotaur

Начальный каркас приложения для настройки Windows. План развития: [IMPLEMENTATION.md](IMPLEMENTATION.md).

## Запуск интерфейса

1. Установить Node.js.
2. Выполнить `npm install`.
3. Выполнить `npm run dev` и открыть адрес из вывода.
4. Для сборки интерфейса: `npm run build`.

## Настольное приложение

Нужны Rust (cargo), Microsoft C++ Build Tools и WebView2, согласно требованиям Tauri 2.

- `npm run desktop` — запуск приложения.
- `npm run desktop:build` — сборка Windows-приложения без установщика, затем упаковка в `releases/`.

Результат: папка `munotaur+<версия>+<yyyyMMdd-HHmmss-fff>` и одноимённый ZIP. Версия берётся из `src-tauri/tauri.conf.json`, время — локальное время сборки. В папке находятся `minotaur.exe`, DLL, все файлы `public/config`, `public/dist`, рабочие сценарии `scripts`. Для переноса распакуйте весь архив и запускайте EXE из полученной папки. На целевом ПК нужен WebView2.

## Что реализовано

- Основной экран: имя компьютера, профиль, план действий и журнал.
- Создание профилей; автоматическое сохранение в локальном хранилище интерфейса.
- Добавление действий из шести встроенных шаблонов, редактирование параметров, отключение, копирование, удаление, изменение порядка.
- Импорт и экспорт профилей JSON.
- Проверка имени компьютера и обязательных действий перед запуском.
- Последовательный пробный запуск с неизменяемой копией профиля.
- В настольном режиме — реальная инвентаризация Windows через CIM/PowerShell.
- Скачивание JSON- и HTML-отчётов с датой, идентификатором запуска и результатами.

## Ограничения текущего прототипа

Запуск демонстрационный: переименование, создание пользователей, установка программ и применение реестра пока не выполняются. Отчёт явно содержит `mode: simulation` и отдельно хранит запрошенное имя и фактические сведения Windows. В браузере оборудование не собирается. HTML-кнопка скачивает файл для открытия.

Встроенные шаблоны сейчас определены в `src/main.js`; редактор пользовательских шаблонов, полноценные схемы параметров, безопасный административный исполнитель, защищённое хранение состояния, перезагрузки и автоматическое сохранение отчётов в ProgramData — следующие этапы. Поля шаблонов пока используют технические названия.

Изменение профилей сохраняется автоматически. Последний отчёт сохраняется в локальном хранилище, файлы отчётов пользователь скачивает кнопками. Секреты в формы профилей не добавлять: защищённое хранилище пока не реализовано.

## Разделы приложения

«Подготовить ПК» и «Конфигурация ПК» имеют независимые профили, результаты и журналы. Старые профили автоматически доступны в разделе подготовки. Редактор «Профили» относится к выбранному разделу. Экспорт содержит раздел; импорт профиля другого раздела отклоняется.

Новые действия PowerShell получают пути `scripts/prepare/setup.ps1` или `scripts/configure/setup.ps1`. В этих каталогах находятся отдельные заготовки сценариев. Текущий исполнитель по-прежнему демонстрационный и не запускает их. Для конфигурации переименование необязательно; итоговый отчёт обязателен в обоих разделах.

## Локальные логи

В desktop-версии события запуска, выполнения шагов и ошибки сохраняются в `logs` рядом с exe; при разработке — в `logs` в корне проекта. Формат — JSONL, отдельный файл на сутки UTC; время записи — Unix milliseconds. В браузерном предпросмотре файлы не создаются. Логи могут содержать вывод запущенных команд.

История сборок автоматически сохраняется в `releases/versions.json` после успешного создания ZIP: версия, относительная ссылка `bundle`, дата ISO 8601, Git-коммит и `changelog`. Новые записи идут первыми. Для первой сборки включается вся история коммитов, далее — коммиты после предыдущей сборки. Без Git-репозитория список изменений пуст, выводится предупреждение.
